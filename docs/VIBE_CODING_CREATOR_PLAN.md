# 面向 Vibe Coding AI 博主的交付计划

## 1. 最终交付目标

`mdldm Knowledge Kit` 的目标用户不是完全不接触技术的 SaaS 客户，也不是需要从领域
模型开始开发的专业工程团队。第一位目标用户是：

> 已经持续发布 AI 内容、稍微理解 Git、环境变量和 Vibe Coding，愿意让 Codex 或其他
> Agent 帮助部署与个性化，但不应该为了日常运营去理解 Next.js、Mongoose、支付回调
> 或权限模型的个人博主。

他拿到仓库后，应当能够：

1. Fork 或 Clone 项目，按 README 或 Agent Prompt 部署；
2. 在自己的 Vercel、MongoDB、OSS、SMTP 和支付账号中完成连接配置；
3. 通过界面完成站点品牌、创作者资料、内容和商品初始化；
4. 在后台持续发布课程、处理订单和查看故障；
5. 用少量、边界清晰的 Prompt 修改视觉风格或增加个人化页面；
6. 把最终站点交给学员注册、购买和学习，而不残留 Demo 品牌与内容。

日常经营能力不能依赖 Agent。Agent 是安装、差异化改造和故障排查的加速器，不是站点
品牌、价格、课程和用户权益的数据后台。

## 2. 当前距离

当前项目已经完成可靠的业务底座，但“拿来即改”的创作者产品层仍在建设。以下进度是
产品判断，不等同于代码覆盖率或生产验收结果。

| 层级 | 当前判断 | 已有能力 | 主要缺口 |
| --- | --- | --- | --- |
| 领域与安全底座 | 基本完成 | 身份、Entitlement、服务端定价、支付幂等、MediaAsset、学习进度 | 继续保持测试和安全边界 |
| Provider 适配 | 官方路径已冻结、未生产验收 | MongoDB、OSS、SMTP、Manual/Mock/XorPay、Agent + Vercel Serverless 协议、脱敏检查 | 开源版独立 Preview、L2/L3 与中国大陆多网络验收 |
| 品牌与站点设置 | 基础完成 | SiteSetting 已接入公开首页、元信息、页头、创作者资料、麦当/极简两套主题和管理员表单 | Logo 上传和推荐内容编排 |
| 内容发现 | 基础完成 | 搜索、分类、Tag、系列详情、Tag 聚合和兼容旧数据的展示链路 | 内容完整编辑、排序、预览和安全删除 |
| 学员体验 | 基础完成 | 学习中心、系列目录、上一课/下一课、订单和安全入口 | 已购内容筛选、移动端播放器细节和更完整空状态 |
| 运营后台 | 进行中 | 已拆出站点、内容、商品、用户、订单、系统分区，站长可修改自己的密码 | 权益、分析，以及内容完整编辑/排序/预览 |
| 首次开站 | 基础完成 | `/admin` 一次性创建首个管理员，`/admin/setup` 保存任务进度、检查真实事实并控制正式开站 | 生产 Provider 实测、失败恢复和陌生用户验收 |
| 交付与验收 | 未完成 | README、部署文档、L0/L1 验证方法 | 陌生 AI 博主的全新部署、真实 Provider 和备份恢复验收 |

因此，项目不需要推翻重写。按“目标 AI 博主拿到后可低成本开站并持续运营”的产品
完成度估算，当前约为 `70%`；这不是生产 Provider 验收通过率。剩余约 `30%` 集中在：

- 一轮运营补全：内容完整 CRUD、用户、权益、分析和 Demo 清理；
- 一轮开站工程收口：生产 Provider 实测、异常恢复和 Agent 改造契约验收；
- 一轮独立验收：使用全新第三方账号跑通 L2/L3，并由未参与开发的目标用户完成。

在上述工作完成前，`v0.1.0` 应继续被描述为“可运行、可二次开发的业务底座”，不能
宣传为“配置完第三方平台即可运营”的成品。

## 3. 后台、外部平台与 Agent 的边界

### 必须通过知识站后台完成

这些是高频运营事实，不能要求站长改代码：

- 站点名称、简介、Logo、创作者资料、客服和公开社交链接；
- 首页文案、导航、推荐内容和页脚；
- 系列、课时、分类、Tag、封面、视频、资料、顺序与发布状态；
- 全站会员和单课商品的名称、服务端价格、期限、权益目标和上下架；
- 用户状态、邀请码、人工权益、订单确认与失败重试；
- Provider 状态、失败队列、基础学习和经营指标；
- Demo 内容的替换或清理。

后台不得接收第三方长期密钥，商品后台也不得允许客户端决定最终成交金额。

### 必须在第三方平台或 Secret Manager 完成

- 域名、DNS、Vercel 项目和环境隔离；
- MongoDB、OSS、SMTP、XorPay 和告警账号开通；
- URI、AccessKey、密码、支付密钥和 Webhook Secret；
- OSS CORS、最小权限 RAM、邮件域名认证和支付回调地址；
- Atlas、OSS 的备份策略和成本告警。

知识站可以检查这些连接，但不能代替第三方平台创建账号、审核资质或保存密钥。

### 适合交给 Agent 完成

- 从模板 Fork、安装依赖、生成 `AUTH_SECRET` 和创建部署；
- 根据站长提供的非敏感信息生成环境变量清单；
- 按文档检查 Provider 配置和解释错误；
- 在现有设计 Token 和组件边界内调整配色、字体、版式与首页栏目；
- 增加已明确范围的个人页面、统计代码或新 Provider Adapter；
- 执行升级、迁移、测试、备份恢复演练和故障定位。

Agent Prompt 必须说明可修改范围、禁止输出的密钥、验收命令和失败后的回滚方式。任何
Prompt 都不能把“命令执行成功”当成第三方生产链路已通过。

## 4. 分阶段实施

### Wave A：成为一个可浏览的知识站

状态：`DONE`

交付：

- SiteSetting 接入公开首页、页头和基础导航；
- 首页展示创作者定位、推荐系列、最近更新和购买/学习入口；
- `/courses` 支持搜索、分类和 Tag；
- `/series/[slug]` 展示系列介绍、目录、权益与学习进度；
- `/tags/[tag]` 提供内容聚合；
- `/account` 提供继续学习、会员和已购内容入口；
- 后台可以编辑内容发现所需的分类、Tag 和封面信息。

完成定义：

- 新站替换后台设置后，公开页面不再显示 `Demo Creator` 或开源项目宣传文案；
- 学员可以从首页在三次交互内找到一个系列并进入可学习或可购买状态；
- 搜索、分类、Tag 和系列链接不存在 404；
- 老数据在没有分类、Tag 和封面时仍能正常展示；
- 相关领域单测、页面测试、类型检查和构建通过。

### Wave B：让日常运营不需要改代码

状态：`IN PROGRESS`

交付：

- 内容后台支持创建、编辑、排序、预览、发布和安全删除；
- 商品后台支持全站会员与单课商品的创建、编辑、上下架和服务端校验；
- 用户、权益、订单、分析和系统后台按运营任务分区；
- 学习页支持系列课时导航、上一课/下一课和明确的权益提示；
- Demo 清理和第一门课程发布有界面化流程。

已完成：后台任务分区、商品创建/编辑/上下架、服务端价格事实源、系列连续导航。
未完成：内容完整编辑/排序/预览/删除、用户与权益后台、分析和 Demo 清理流程。

完成定义：

- 站长不修改 TypeScript 即可完成一次课程上新；
- 修改商品不会允许客户端改价，并保留下单时的 `OrderItem` 快照；
- 站长能从后台找到用户、订单、权益、媒体和主要故障；
- 内容删除、商品下架和权益撤销均有确认、审计与必要测试。

### Wave C：让第一次开站可以交给 Agent 协作

状态：`IN PROGRESS`

交付：

- 一次性 `/admin` 初始化入口安全创建首个管理员；
- Provider 状态显示“未配置、可降级、连接失败、已验证”的准确区别；
- 初始化向导完成站点、商品、第一门课程和上线前检查；
- 提供按任务拆分的 Prompt：部署、Provider、品牌改造、内容迁移、上线验收；
- 文档写清 Agent 可编辑文件、数据迁移边界、质量命令和回滚点。

已完成：Agent + Vercel Serverless 唯一线上协议、Preview/Production 双确认、只读技术
检查、脱敏报告、本地 Docker 边界，以及本地启动、部署、Provider、品牌、图文和上线
验收六类任务 Prompt；`pnpm agent:status` 与后台使用同一份脱敏生命周期事实；
`pnpm run doctor --issue` 只生成通过隐私扫描的本地草稿，Agent Report 与 Explore Submission
都保留人工提交确认点；麦当 mdldm 与极简主题已共享语义 Token；AF-11 已将
Page、Route Handler 和 Client Component 与 MongoDB Model 解耦，建立 Query Service、
Repository Port、安全 DTO 和架构回归测试。仍未完成：全新隔离账号 L2/L3
和中国大陆多网络真实验收。

完成定义：

- 初始化完成后 `/admin` 不能再次创建首个管理员，`/setup` 只兼容跳转到受保护的
  `/admin/setup`；
- 页面和日志不回显密钥、URI 或敏感外部标识；
- 用户可以只把 Prompt 和自己的非敏感目标交给 Agent，不需要自己设计修改方案；
- Agent 修改后仍必须通过 `pnpm check`、相关 E2E 和公开仓库审计。

### Wave D：真实第三方平台和目标用户验收

状态：`TODO`

交付：

- 创建开源版独立 Preview，不复用原站数据、密钥、Bucket 或支付回调；
- 对 MongoDB、OSS、SMTP、XorPay、Vercel 完成并记录 L2/L3；
- 使用自定义域名从至少两个中国大陆网络点验收首页、登录、后台、学习页和媒体；
- 完成 Atlas 与 OSS 备份和隔离恢复；
- 邀请未参与开发、稍懂 Vibe Coding 的 AI 博主完成全新开站；
- 修复验收阻断项后发布 `v0.2.0`。

完成定义：

- “Provider Adapter 存在”和“目标用户账号已生产可用”在界面与文档中明确区分；
- 测试者能够独立完成下面的真实验收旅程；
- 验收记录只保存状态、耗时、错误分类和修复建议，不保存真实凭据与业务数据；
- 所有发布门禁通过，Demo 品牌、测试商品和测试账号可安全清理。

## 5. 真实验收旅程

验收人必须是未参与实现的目标用户，使用全新 Fork、全新部署和独立第三方测试账号。

```text
看到 GitHub 项目
  → 判断适用范围并 Fork
  → 用 README 或部署 Prompt 上线 Preview
  → 配置 MongoDB、OSS、SMTP、支付与域名
  → 打开 /admin，两次确认自己的邮箱并创建管理员 1 号
  → 保存一次性临时密码并设置正式密码
  → 在 /admin/setup 完成开站任务和上线检查
  → 填写自己的品牌和创作者资料
  → 创建一个系列、分类、Tag 和两节课程
  → 上传封面、视频和资料
  → 创建全站会员与单课商品
  → 用访客、注册用户、会员、单课用户分别验权
  → 完成一笔隔离低价支付并确认幂等授权
  → 在学习中心续播并完成系列学习
  → 在后台找到订单、用户、权益和一次模拟故障
  → 完成备份和隔离恢复
  → 清理 Demo 与测试数据并正式开放
```

每一步记录：

- 用户是否知道这一步的意义；
- 是否能判断下一步；
- 是否必须离开界面查代码；
- Agent Prompt 是否给出足够边界；
- 首次完成时间；
- 阻断错误、恢复方式和最终证据。

## 6. `v0.2.0` 总完成定义

只有同时满足以下条件，才能把项目交付给目标 AI 博主：

1. Fork 后按 README 或内置 Prompt 可以建立独立 Preview；
2. 第三方密钥只存在于部署平台或 Secret Manager；
3. 日常品牌、内容、商品、用户和订单运营不需要修改 TypeScript；
4. 搜索、分类、Tag、系列详情、学习中心和主要后台分区完整可达；
5. 全站会员和单课购买都通过服务端价格与统一 Entitlement；
6. 首个管理员初始化具备一次性安全边界；
7. Provider 未配置和 Provider 已生产验证在界面上不会混淆；
8. MongoDB、OSS、SMTP、支付、学习、备份和恢复完成隔离环境验收；
9. 一个未参与开发的目标用户完成真实旅程，且没有 P0/P1 阻断项；
10. 代码、测试、文档、迁移说明和发布审计同时完成。

## 7. 不在本阶段解决

- 多租户 SaaS 和托管控制台；
- 麦当个人品牌、真实课程和用户数据迁移；
- 飞书群、微信小程序、返佣、提现和私有 AI 网关；
- 为所有创作者提供无限制的页面搭建器；
- 用 AI 搜索掩盖基础分类、Tag 和内容信息架构缺失。

优先完成稳定的创作者模板和清晰扩展点，再由 Agent 在单个部署者自己的 Fork 中完成
差异化。
