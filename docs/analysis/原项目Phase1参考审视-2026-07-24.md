## 3. 明确不参考的实现

| 原项目实现 | 不采用原因 | 新仓替代 |
| --- | --- | --- |
| 巨型客户端首页 `app/page.tsx` | 品牌、营销、AI、会员和课程查询集中在单一页面 | Server Component 首页与可配置 Site 模块 |
| `next.config.ts` 构建时跳过 ESLint | 会让质量问题进入发布产物 | Lint、类型、单测和构建全部作为质量门 |
| 注册接口读取客户端 `role` | 存在管理员角色注入风险 | 服务端固定普通用户，管理员由受控脚本创建 |
| 支付接口读取客户端 `price`、`name` 和 `more` | 客户端可影响最终商品与金额 | 服务端 Product/SKU 决定价格和权益 |
| `User` 同时保存 VIP、积分、返佣、微信、AI Key 和飞书字段 | 核心账号模型被个人业务污染 | Identity 只保留账号、角色、状态和验证信息 |
| `isVIP` / `isVip` 分散判断 | 权限规则没有统一事实源 | Entitlement 服务统一判断 |
| `instrumentation.ts` 直接导入飞书 | Operations 与固定告警渠道耦合 | Observability Port 与 Console 默认实现 |
| OSS、MPS、XorPay 直接进入路由 | 核心业务无法在无第三方配置时运行 | Provider Adapter 和明确降级 |
| 原站首页数据与真实内容 | 含个人品牌和业务信息 | 新仓只使用虚构 Demo 数据 |
