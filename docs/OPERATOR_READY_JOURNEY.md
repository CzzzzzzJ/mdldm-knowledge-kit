# Phase 7：小白可运营用户旅程

## 1. 目标

`v0.2` 的第一目标不是增加更多功能，而是让一个不了解原项目、也不熟悉
Next.js 的创作者，在完成第三方平台配置后，可以直接开始运营自己的知识站。

站长引导不是独立课程站或第二个项目。它直接位于当前知识站的 `/setup`，读取当前
项目的公开运行配置和健康检查，并把用户带回现有课程、价格、注册与后台页面。浏览器
中的“已理解”只记录教学进度，不替代 Provider 验证或服务端初始化状态。

目标用户只需要理解：

- 自己的站点名称、Logo、介绍和联系方式；
- 要发布什么系列、课程、视频和资料；
- 要售卖全站会员还是单课；
- 如何处理用户、订单、权益和故障。

用户不应为了日常运营去修改 TypeScript、Mongoose Schema 或 API Route。

## 2. 配置边界

### 仍由环境变量管理

以下信息属于基础设施或密钥，只通过 Vercel Environment Variables、
`.env.local` 或 Secret Manager 注入：

- 应用正式 URL；
- MongoDB URI；
- Session/Auth Secret；
- OSS AccessKey、Bucket 与 Region；
- SMTP 主机、账号和密码；
- XorPay AID、App Secret 与回调基础配置；
- 告警 Webhook URL 与签名密钥。

### 改由后台管理

以下信息不应要求部署者修改代码：

- 站点名称、Logo、简介、页脚和客服联系方式；
- 创作者资料和社交链接；
- 首页栏目、导航和推荐系列；
- 会员名称、价格、有效期和权益说明；
- 单课商品、价格、目标课程和有效期；
- 系列、课程、封面、视频、资料、排序和发布状态；
- 用户状态、人工权益、邀请码和订单处置说明。

核心原则：

> 环境变量负责“连接服务”，运营后台负责“经营知识站”。

## 3. 第一次上线旅程

```text
Fork / Clone
  → 部署到 Vercel 或自有 Node.js 环境
  → 配置 MongoDB、OSS、SMTP、支付和 Auth Secret
  → 打开 /setup
  → 运行自动配置检查
  → 创建首个管理员
  → 设置站点品牌和联系方式
  → 创建全站会员或单课商品
  → 创建系列与第一节课程
  → 上传封面、视频和资料
  → 预览访客、会员和单课用户路径
  → 完成上线检查
  → 正式开放注册与购买
```

`/setup` 只能在站点尚未初始化时进入。初始化完成后，设置继续在受保护的
管理员后台维护，不能再次通过公开入口创建管理员。

## 4. 基础页面重构

### 访客与学员页面

| 页面 | 目标 |
| --- | --- |
| `/` | 展示创作者、知识站定位、推荐系列、最近更新和核心 CTA |
| `/courses` | 分类、搜索和浏览全部已发布系列与课程 |
| `/series/[slug]` | 展示系列介绍、课程目录、学习进度、价格与权益状态 |
| `/learn/[courseId]` | 视频、资料、课时导航、进度和下一课 |
| `/pricing` | 清晰解释全站会员与单课购买的区别 |
| `/account` | 汇总会员状态、已购课程、继续学习和账号入口 |
| `/account/orders` | 查看订单、支付与履约状态 |
| `/account/security` | 修改密码、会话和账号安全 |

### 管理员页面

| 页面 | 目标 |
| --- | --- |
| `/admin` | 今日待办、经营概览、异常和快捷入口 |
| `/admin/site` | 品牌、首页、导航、页脚和联系方式 |
| `/admin/catalog` | 系列、课程、媒体、资料、排序和发布 |
| `/admin/products` | 会员、单课商品、价格、期限和上下架 |
| `/admin/users` | 用户状态、注册时间、会员与已购课程 |
| `/admin/entitlements` | 邀请码、人工授权、到期和撤销 |
| `/admin/orders` | 订单、支付、履约、人工确认和重试 |
| `/admin/analytics` | 注册、购买、学习和完课的基础指标 |
| `/admin/system` | Provider 状态、失败队列、备份和上线检查 |

页面可以先共用一个应用，但路由与信息架构必须按运营任务拆分，不能继续把所有
表单堆在一张管理员页面中。

## 5. 最小运营闭环

### 每日

- 查看新订单和支付失败；
- 查看待处理用户或权益问题；
- 查看媒体、邮件和存储失败；
- 回复课程反馈或记录问题。

### 每周

- 发布或更新课程；
- 查看注册、购买、学习和完课趋势；
- 检查即将到期会员；
- 导出必要运营快照；
- 检查 Atlas 与 OSS 备份状态。

### 上新

1. 创建系列或选择已有系列；
2. 新建草稿课时；
3. 上传封面、视频和资料；
4. 设置访问级别和对应商品；
5. 使用预览账号检查公开、会员和单课权限；
6. 发布；
7. 检查学习和支付路径。

### 故障

1. 从 `/admin/system` 查看失败类型和 Provider；
2. 跳转到关联订单、媒体或用户；
3. 修复外部配置或重试业务动作；
4. 写入处理说明；
5. 确认相同故障再次发生时会重新打开。

## 6. 从原项目提取的公共经验

原项目只作为产品事实来源。Phase 7 参考以下已经被真实运营使用过的通用表面：

- 品牌首页、精选课程与最近更新；
- 系列详情、课程目录和继续学习；
- 个人中心、会员状态和邀请码；
- 经营总览、用户、课程、订单、权益与学习分析；
- 内容上新、邮件通知和故障处置的操作习惯。

以下能力不进入 `v0.2` 公共核心：

- 麦子、AI 网关和模型额度；
- 飞书知识库、VIP 群和个人 Webhook；
- 微信小程序、二维码绑定和微信登录；
- 推荐返佣、佣金冻结与提现；
- MDTI、M-Agent 和个人营销页面；
- 原项目真实用户、订单、课程、域名、Bucket 和密钥。

## 7. `v0.2` 验收门槛

邀请一名未参与开发的测试者，从全新仓库和全新第三方测试账号开始。只有同时满足
以下条件才算完成：

1. 只读 README 和界面提示完成部署；
2. 配置后能在 `/setup` 看懂每个 Provider 的状态和修复建议；
3. 不修改 TypeScript 即可完成品牌、商品和第一门课程配置；
4. 能跑通注册、邮件验证、会员购买、单课购买和邀请码；
5. 未授权用户无法播放或下载受控内容；
6. 管理员能处理人工订单、授权失败和媒体失败；
7. 能完成 Atlas 与 OSS 的备份和隔离恢复演练；
8. 能把 Demo 内容清空或替换，不残留 `Demo Creator` 和示例商品；
9. 全过程不接触原项目真实数据或凭据；
10. 验收过程、结果、失败和修复全部记录在仓库文档中。
