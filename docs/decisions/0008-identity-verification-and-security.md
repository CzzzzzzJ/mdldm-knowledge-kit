# ADR 0008：身份验证、凭据恢复与安全边界

- 状态：Accepted
- 日期：2026-07-24

## 背景

Phase 3 需要开放普通用户注册，同时修复原项目允许客户端参与角色决定、身份流程分散和多实例限流失效等问题。Vercel 等平台会横向扩缩容，单进程内存不能成为认证限流的事实来源。

## 决策

- 公共注册接口只接受名称、邮箱和密码，并使用严格输入 Schema；任何额外 `role` 字段都拒绝；
- 新用户角色由服务端固定为 `user`，管理员仍只通过受控脚本创建；
- 普通用户必须验证邮箱后才能创建会话；
- 邮箱验证和密码重置 Token 使用高熵随机值，数据库只保存 HMAC 摘要；
- Token 有明确用途、有效期、单次使用状态和 TTL 清理索引；
- 密码重置与修改密码后删除该用户全部旧会话，再创建当前新会话；
- Cookie 保持 `httpOnly`、生产环境 `secure`、`sameSite=lax` 和明确过期时间；
- 所有写接口执行同源检查；全站响应加入 CSP、frame、MIME、Referrer、Permissions Policy 和生产 HSTS；
- 登录、注册、验证、找回、改密和邀请码兑换使用 MongoDB 固定窗口限流桶，使多实例共享状态；
- 找回密码和重发验证邮件使用统一响应，避免通过响应枚举邮箱。

## 备选方案

### 允许注册后立即登录

体验更短，但无法确认邮箱所有权，也会削弱找回密码链路。

### JWT 无状态会话

减少数据库读取，但禁用用户、改密和撤销会话时难以及时回收。v0.1 保留服务端 Session。

### 进程内限流

本地实现简单，但 Vercel 多实例之间不共享计数，不能作为生产安全边界。

## 影响

- Console Email 仅用于本地开发；生产环境应配置 SMTP；
- `AUTH_SECRET` 同时保护会话、身份 Token 摘要、邀请码摘要和限流键摘要，轮换需要安排用户重新登录，并使未使用链接和邀请码失效；
- 邮箱发送失败不会提升账号权限，用户可使用重发入口恢复；
- 后续外部登录 Provider 仍必须映射到同一 User、Session 和 Entitlement 模型。
