# ADR 0012：面向小白运营的初始化与站点设置边界

- 状态：Accepted
- 日期：2026-07-27

## 背景

`v0.1.0` 已验证陌生开发者可以在 15 分钟内启动 Demo，但站点品牌、商品和部分
初始化动作仍依赖环境变量、TypeScript 配置与终端脚本。该标准证明了代码可运行，
没有证明不了解 Next.js 的创作者可以在配置第三方平台后直接运营。

原私有项目已经形成品牌首页、系列详情、个人中心和多分区运营后台，但实现中混入
个人品牌、私有业务、固定 Provider 和真实配置，不能直接复制。

## 决策

Phase 7 保留现有单仓模块化技术架构，新增面向运营的产品框架：

1. 环境变量只保存基础设施连接、密钥和启动级开关；
2. SiteSetting、导航、创作者资料、首页栏目和非敏感运营设置进入数据库；
3. Product/SKU 仍由服务端决定价格和权益，但增加受保护的后台管理用例；
4. 新站通过一次性 `/setup` 完成 Provider 检查、首个管理员和站点初始化；
5. 初始化完成后公开 setup 入口关闭，后续设置只能由管理员修改；
6. 用户端补齐品牌首页、系列详情、学习中心和个人中心；
7. 后台按站点、内容、商品、用户权益、订单、分析和系统分区；
8. Provider 验收分为 L0 配置、L1 只读连接、L2 隔离写入和 L3 业务全链路；
9. 原项目只提供配置结构和运营事实，真实值、数据、品牌和私有插件不得迁移。

商品管理不能重新引入客户端定价。管理员提交的商品变更必须经过运行时校验，
服务端持久化并保留下单时的 OrderItem 快照。

## 备选方案

### 先接入所有真实第三方平台

可以验证 Provider，但当前页面和初始化流程改变后需要重复验收，且不能回答新手是否
能运营。

### 推翻现有架构并复制原项目

可以快速获得更多页面，但会重新引入 `isVIP`、Provider 直连、私有字段和历史安全
问题。

### 继续依赖配置文件和脚本

适合开发者模板，不符合“配置第三方平台后直接运营”的产品目标。

## 影响

- 需要新增 SiteSetting 持久化模型、初始化状态和对应管理 API；
- Product/SKU 需要从静态种子升级为数据库事实源与后台管理；
- `/setup` 和后台设置涉及高权限写操作，必须有集成或 E2E 测试；
- 现有 `config/site.config.ts` 与 `config/products.config.ts` 保留为安全默认值和
  Seed，不再成为日常运营入口；
- 页面与导航会在 `v0.2` 重新设计，但 `modules/`、`providers/`、Entitlement、
  MediaAsset 和 PaymentEvent 边界保持不变；
- Phase 7 完成后必须由未参与开发的测试者在全新第三方测试环境中验收。
