# ADR 0013：首个管理员与站点生命周期

- 状态：Accepted
- 日期：2026-07-31
- 修订：2026-08-03（管理员 1 号临时凭据与强制激活）

## 背景

旧的首次开站体验把 `/setup` 作为公开教学页，教学进度只保存在浏览器中，首个管理员
仍依赖终端脚本创建。项目启动后，首页、注册和购买立即可用，站长无法判断网站处于
配置阶段还是已经正式运营。

ADR 0012 已要求一次性初始化、首个管理员和初始化完成后关闭公开 Setup，本决策补齐
具体安全边界与生命周期。

## 决策

1. 站点生命周期由 `SiteInitialization` 单例记录，状态为 `configuring` 或 `live`；
2. 没有初始化记录且数据库中没有管理员时，视为 `uninitialized`；
3. 未初始化站点访问公开页面时进入 `/admin`，部署者两次输入自己的邮箱；两次标准化
   结果一致后，该邮箱直接成为“管理员 1 号”的登录账号；
4. 生产环境创建首个管理员必须同时提供 `INITIAL_SETUP_TOKEN`；
5. 首个管理员创建使用数据库唯一单例和短期 claim，避免并发请求创建多个首个管理员；
6. 系统使用密码学安全随机数生成本次初始化独有的临时密码，只在成功响应和当前页面
   中展示一次；数据库只保存 bcrypt 哈希；
7. 创建成功后立即建立管理员会话并进入 `/admin/activate`；正式密码完成轮换前，页面、
   公开预览和后台 API 都不得绕过激活门禁；
8. 正式密码保存后撤销所有旧会话、使临时密码失效，并建立新的管理员会话进入
   `/admin/setup`；
9. 开站教学进度保存到 `SiteInitialization.completedLessons`，不再使用浏览器存储作为事实源；
10. 正式开站前服务端检查管理员、Provider、SiteSetting、已发布课程、可售商品和教学任务；
11. 站点未进入 `live` 时，普通访客不能访问公开内容、注册或购买，已激活管理员仍可预览；
12. `/setup` 只保留兼容重定向，开站指南和上线检查位于受保护的后台；
13. 公开站点导航不展示后台入口，后台使用独立 Shell 和账号操作。

## 安全边界

- `INITIAL_SETUP_TOKEN` 只能通过部署平台环境变量或本地 `.env.local` 注入；
- Token 不进入数据库、日志、服务端渲染数据或公开运行配置；
- 初始化接口使用同源校验、速率限制、运行时输入校验和常量时间 Token 比较；
- 首个管理员创建完成后，初始化接口对后续请求返回冲突；
- 临时密码响应显式使用 `Cache-Control: no-store`，前端只保留在当前 React 内存状态，
  不写入 URL、Cookie、localStorage 或 sessionStorage；
- `User.requiresPasswordChange` 是激活门禁事实；旧用户缺少该字段时按 `false` 兼容；
- 普通注册接口不能指定角色，仍只创建普通用户；
- 正常修改管理员密码继续要求当前密码，并使其他会话失效；首次激活使用已经建立的
  一次性管理员会话，并要求两次输入正式密码。

## 兼容策略

升级前已经存在管理员但没有 `SiteInitialization` 的站点，读取时推断为
`configuring`。管理员登录 `/admin` 后会进入开站指南，并生成正式初始化记录。
现有 `create-admin` 脚本作为本地自动化和故障恢复入口保留，但不再是新手默认路径。
脚本只在显式传入 `--reset-existing` 且邮箱属于现有管理员时执行受控密码重置，并撤销
该管理员的全部会话；不会提权普通用户或创建第二个首个管理员。

## 影响

- `User` 新增向后兼容的 `requiresPasswordChange` 默认字段；不需要离线数据迁移；
- 新增首次管理员创建与激活 API、后台进度 API 和开站 API；
- 公开页面、注册和购买增加站点生命周期门禁；
- E2E 必须显式准备 `live` 状态，避免测试依赖隐式公开；
- README、部署文档和 Demo 顺序改为先访问 `/admin` 创建管理员；
- 未来若增加重新开站或维护模式，需要新增 ADR，不复用首个管理员入口。
